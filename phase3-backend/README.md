# HealthTrack Phase 3: Backend Implementation

FastAPI and SQLAlchemy backend for the HealthTrack remote cardiac rehabilitation monitor. It implements the Phase 2
design for patients, vital signs, daily activity, and devices, with JWT authentication, care-team authorization,
an append-only audit log, Alembic migrations, a 236-test suite, and a Postman collection. All data is synthetic.

## Setup (macOS, Linux, or Windows)

Requires Python 3.10 to 3.14 (`.python-version` pins 3.12 for uv). PostgreSQL is optional; SQLite is used by default.

With [uv](https://docs.astral.sh/uv/) (recommended):

```bash
cd phase3-backend
uv venv                              # creates .venv with the Python in .python-version (downloads it if needed)
source .venv/bin/activate            # Windows: .venv\Scripts\activate
uv pip install -r requirements-dev.txt

python3 -m alembic upgrade head      # creates healthtrack.db with migrations 0001 and 0002
python3 -m scripts.seed              # loads the synthetic sample data
python3 -m uvicorn app.main:app --reload
```

With plain pip, replace the first three commands with `python3 -m venv .venv`, `source .venv/bin/activate`, and
`pip install -r requirements-dev.txt`. Every pinned dependency ships prebuilt wheels for Python 3.10 to 3.14, so
nothing needs to compile.

Open **http://localhost:8000/docs**, click **Authorize**, and log in as `marcus.lee@healthtrack.example` with the
mock password `HealthTrack-Demo-2026!`.

To use PostgreSQL instead: `export HT_DATABASE_URL=postgresql+psycopg://user@localhost:5432/healthtrack` before
running the migration and seed commands. See `.env.example` for every setting.

## Tests and reports

```bash
python3 -m pytest                              # 236 tests on in-memory SQLite, a few seconds
python3 -m pytest --cov=app                    # with coverage
HT_TEST_DATABASE_URL=postgresql+psycopg://user@localhost/healthtrack_test python3 -m pytest   # same suite on PostgreSQL
./scripts/run_reports.sh                       # tests + coverage + benchmark + OpenAPI export into reports/ and docs/
```

## Postman

Import `postman/HealthTrack_Phase3.postman_collection.json` and `postman/HealthTrack_local.postman_environment.json`,
start the server on a freshly seeded database, and run the collection with the Collection Runner. The login requests
save tokens automatically; every request asserts its expected status code (43 requests, 64 assertions).

## Layout

```
app/
  main.py                 app factory, middleware (request id, security headers, access log)
  config.py               settings from HT_* environment variables
  db.py                   engine, session factory, per-request session
  security.py             bcrypt, JWT, refresh tokens, TOTP, login rate limiter
  errors.py               domain exceptions
  models/                 SQLAlchemy models: User, AuthSession, Patient, CareTeamAssignment,
                          VitalSign, DailyActivity, Device, AuditLog
  schemas/                Pydantic request and response models with validation rules
  repositories/           data access layer (see docs/DATA_ACCESS.md)
  api/                    routes, auth and scope dependencies, problem+json error handlers
migrations/versions/      0001 initial schema, 0002 device registry (schema update)
tests/                    model, repository, schema, security, migration, and API tests
scripts/                  seed, benchmark, test report, OpenAPI export, Postman builder
docs/                     DATA_ACCESS.md, API_GUIDE.md, openapi.json, openapi.yaml
postman/                  collection and environment
reports/                  generated by run_reports.sh: test results, coverage, performance
```
